# Хроника — заметки для работы с кодом

Локальная текстовая RPG: ИИ-рассказчик через OpenRouter, отдельный проход «учётчик» ведёт структурированное состояние мира (листы героев, НПС, сцена, нити, хроника фактов, лорбук). Node 18+, Express, без сборки; фронтенд — обычные (не модульные) скрипты `public/js/*.js` + `index.html` + `styles.css`. Пользователь общается по-русски, весь интерфейс и промты на русском.

Подробная история решений и бэклог — в `docs/HISTORY.md`. Прочитай его перед заметными изменениями в учётчике, промтах или интерфейсе НПС.
Столкновения (бой и прочие противостояния) — договорённости в `docs/ENCOUNTERS.md` (черновик, обсуждается с пользователем; кода ещё нет).

## Запуск и проверка

- `npm install`, `.env` с `OPENROUTER_API_KEY`, `node server.js` (порт 3000). После правок пользователь перезапускает сервер и обновляет страницу Ctrl+F5.
- Версия интерфейса печатается в консоль браузера второй строкой `public/js/core.js`: `console.log('AI Storyteller UI vNN — …')`. **Повышай номер при каждом изменении фронтенда** — по нему пользователь проверяет, что подхватилась новая версия. Сейчас v54.
- **Проверки — перед каждым коммитом:** `npm test` (node:test, без сети: данные во временной папке, OpenRouter подменён) и при правках интерфейса `npm run test:ui` (Playwright, сервер с поддельной моделью, экраны компьютера и телефона; `UI_SHOTS=папка` сохраняет скриншоты). Нашёл ошибку — сначала тест, который её ловит, потом исправление.
  - `test/fake-llm.js` — `reply()`, `call()`, подмена `fetch` в процессе (для `src/*`); `test/harness.js` — настоящий `server.js` в отдельном процессе + поддельный OpenRouter/A1111 (`OPENROUTER_URL`, `STORYTELLER_DATA_DIR`); `test/helpers.js` — `makeState()`.
  - Учётчик на настоящей модели: `npm run eval:sync -- --model …` (сцены в `evals/sync-scenes.js`, отчёт в `data/evals/`). Меняешь промт учётчика или `completenessHints` — попроси пользователя прогнать до и после и сравнить цифры. Новая сцена: `must`/`forbid` проверяют итоговый мир, `ideal` — вызовы идеального учётчика (по ним `npm test` проверяет саму сцену).
  - Перед коммитом крупных переносов сравнивай список функций и маршрутов с прежней версией (`grep -oE "^(export )?(async )?function \w+"`, `grep -oE "app\.(get|post|put|delete)\('[^']+'"`) — однажды при замене блока случайно удалилось сжатие истории.
- Данные лежат в `data/` (в `.gitignore`; `STORYTELLER_DATA_DIR` переносит их): `settings.json` (общие настройки), `slots.json` + `slots/<id>.json` (партии), `slots/<id>.turns/<index>.json` (варианты ходов со снимками мира), `avatars/`, `scenes/`, `diag/`.

### Ход
1. Рассказчик (`narrate`) — без инструментов, кроме `roll_check` (бросок до описания, исход считает код) и `codex_lookup` (прочитать статью кодекса до описания). Сообщения помечаются героем (`hero`), при нескольких героях `labelHeroes` добавляет пометки «[Ход за героя …]».
2. Учётчик (`syncState`) — модель учёта (`toolModel`, иначе основная). Раунд 1 `tool_choice: required` (+ `nothing`). Раунд 2 — если результат инструмента совпал с `FIX_SIGNAL` (ошибка/«не найден»/ВНИМАНИЕ), ответ оборвался, или `completenessHints` нашёл во фрагменте признаки события без вызова (оплата, ранение, отдых, расход предметов, прошло время, кто-то ушёл, исполнено обязательство из хроники).
3. `afterSync` — противоречия, замечания для следующего хода. Затем ответ клиенту, и в фоне сжатие истории (пачкой: при `historyKeep + historyKeep/4` сообщений, срезая до `historyKeep`; результат применяется, только если история не изменилась).

Журнал учёта хранится у реплики (`entry.sync.calls`), показывается под ответом; «переучесть ход» откатывает к `preSync` и прогоняет учёт заново (можно другой моделью).

### Промт учётчика
Постоянная часть — в начале (кэш провайдера), изменчивая («СЕЙЧАС ОСОБО», справочники для новых НПС, каталог состояний) — в конце. По умолчанию техническая инструкция (`technicalSyncHead`: алгоритм, карта «событие → инструмент», шкала перевода последствий в числа, поля НПС, связки, запреты, пример); прежняя — `legacySyncHead`, переключается настройкой `syncPromptStyle`. Размер ~1600 токенов без справочников новых НПС; следи, чтобы не раздувался.

## Договорённости

- **Учётчик пишет только подтверждённое текстом**, но переводит последствия в числа по шкале. Новые правила — короткими строками, без «семи блоков вопросов»: длинные чек-листы провоцируют лишние записи.
- **Ошибки инструментов — с подсказкой для второго раунда**: что есть на самом деле, как назвать точно (см. удаление блоков/архивацию НПС).
- **Ручные правки переживают откат хода** (перегенерация, свайп, обрезка, сбой): каждая ручная правка (кодекс, НПС, лист, внешность героя, нити, хроника, сцена) пишется в `state.manual` через `noteManual(kind, id, before, after)` — по полям, с временем у каждого; снимки (`captureFullSnapshot`) несут `at`, а `applySnapshot` после восстановления накладывает правки новее снимка (`applyManualOverlay`). Новая ручная правка — не забудь `noteManual`.
- **Закреплённое игроком не меняется**: `block.locked` (целиком), `block.descLocked` (только описание/имя, значение меняется), `npc.locked[]` по полям, `character.locked` (`appearance`, `social`), `scene.locked`, `event.locked`.
- **НПС не удаляются учётчиком — только в архив** (`archived`), при архивации убираются из `scene.present`. При переименовании прежнее имя сохраняется в `npc.aliases`.
- **Промт не растёт без предела**: давно не появлявшиеся НПС — только по имени, накопительные поля — последние пункты (`tailItems`), кодекс — в бюджете 1200 токенов (полное → выжимка → «не поместилось»). Проверяй размер через «Диагностика → Состав промта».
- **Сложность — про мир, не про злость персонажей**: уровни (`DIFFICULTY_DIRECTIVES`) — одинаковые пункты «удача / цена ошибки / опасность»; поведение людей — `PEOPLE_RULES`, одинаковое на любой сложности (свои интересы, вежливо-деловито с незнакомцем, помощь чего-то стоит, торг вместо мгновенного компромисса, без беспричинной вражды).
- **Знание персонажей**: НПС знает о герое только виденное сам (`lastSeen`, свидетели перемен внешности) — рассказчику это показывается в карточках. Темы сценария — направление, а не обязательная вставка в каждую сцену (так персонажи заговаривали невпопад).
- **Нечёткие совпадения — только однозначные**: если кандидатов несколько, ничего не делать и вернуть список похожих.
- Сохранения пишутся атомарно (временный файл + переименование); повреждённый файл не затирается молча, а копируется в `*.broken-<время>`.
- Фронтенд: после любого действия — единый `applyState`/`applyTurnResult`, без частичных обновлений ленты; не рисовать кнопки последней реплики, пока `sending`.
- Стиль UI: тёмный «чернила + латунь» (`--ink`, `--brass`, Cormorant Garamond для заголовков/имён, Spectral для текста, JetBrains Mono для мелких меток). Цветом выделять смысл (отношение НПС), а не раскрашивать поля.
- Картинки: Pony SDXL, по умолчанию аниме-пресет; в негативах обязательно `child, teen, young, loli, shota`, в тегах внешности — явный взрослый возраст.
- Пользователь получает изменения как готовый к запуску проект; объясняй ему результат простыми словами по-русски, без внутренних названий функций.
