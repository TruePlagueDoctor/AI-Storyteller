# Хроника — текстовая RPG с ИИ-рассказчиком

Рассказчик — языковая модель через OpenRouter. Но в отличие от чистого чата,
состоянием игры владеет **код**: листы героев, карточки НПС, черты характера,
броски и справочник мира хранятся структурно и подставляются модели каждый ход.
Модель рассказывает — приложение следит, чтобы мир оставался последовательным.

## Запуск

Нужен Node.js 18+ (https://nodejs.org, версия LTS).

**Windows — двойным щелчком:**
- `Запуск.bat` — при первом запуске сам поставит зависимости и создаст `.env`
  (откроется Блокнот — впиши ключ), затем запустит сервер и откроет игру в браузере.
- `Обновить.bat` — подтянет свежую версию с GitHub (через git или архивом),
  не трогая партии (`data`) и ключ (`.env`). Перед обновлением закрой окно сервера.

**Вручную:**

```bash
npm install
cp .env.example .env      # впиши OPENROUTER_API_KEY (ключ: https://openrouter.ai/keys)
npm start                 # http://localhost:3000
```

На Windows в PowerShell вместо `npm start` может понадобиться `npm.cmd start`.

После обновления файлов **перезапускай сервер** — код в `src/` и `server.js`
читается только при старте. Версию интерфейса видно в консоли браузера (F12).

## Как устроен ход

1. **Рассказ.** Модель получает контекст (промт рассказчика, мир, сценарий,
   предыстория, релевантные записи лорбука, герои в сцене, встреченные НПС,
   сложность, лицо повествования) и пишет ответ. Инструментов у неё нет —
   кроме `roll_check`, если включены броски.
2. **Учёт.** Отдельный короткий запрос сверяет фрагмент истории с состоянием и
   вызывает инструменты: блоки героя, карточки НПС, записи о мире. Промт учёта
   собирается под сцену — правила о замках, переименовании и т.п. включаются
   только когда применимы. Пропускается на чисто описательных ходах.
3. **Проверка.** Код сверяет текст с состоянием: мёртвый персонаж действует,
   герой при смерти описан бодрым, показатель выше максимума. Числовое чинится
   сразу, смысловое уходит рассказчику замечанием на следующий ход.
4. **Сжатие.** Когда сырых ходов больше лимита, старые сворачиваются в
   «Предысторию» (резка строго по границе хода игрока).

## Что есть

**Герои.** Несколько героев в одной истории, у каждого свой лист (показатели,
состояния, инвентарь, умения с уровнем владения, отношения с фракциями) и
паспорт (раса, положение, внешность, портрет). Флажок «В истории» убирает
героя из контекста, не удаляя его — переключается кружком на вкладке.

**НПС.** Карточки с полями «кто это» (постоянное), внешность, характер,
«что было с героем» (накапливается), отношение, статус, портрет. Черты
характера из пула. Замочек на любом поле запрещает рассказчику его менять.
Переименование без дублей: «Девочка с хвостиком» → «Рита» сливает записи.

**Умелость НПС.** У значимых персонажей — «обычный / профессионал / мастер»
и пара ключевых умений. Проверки героя против этих умений труднее (−2 / −4):
следователя сложнее обмануть, стражу — обойти, мастера клинка — перефехтовать.
Учётчик заполняет это у новых персонажей с ремеслом, игрок правит в досье.

**Черты характера.** Пул из ~60 черт в четырёх категориях (нрав, отношение к
людям, пороки, речь), редактируется в настройках. У черты есть пояснение для
рассказчика и влияние на броски: труса легче запугать, упрямца труднее убедить.

**Броски.** Исход рискованных действий решает d20 + бонус умения − штраф за
раны ± черты цели, а не модель. Рассказчик только описывает результат.

**Рост умений.** Опыт дают удачные проверки и тренировки в истории: сам
упражнялся — +1, учился у наставника — +2 (раз в игровой день на умение).
На порогах уровень растёт: новичок → ученик → опытный → мастер. Сколько
осталось до следующего уровня, видно в досье героя.

**Кодекс мира.** Статьи по разделам: народы, бестиарий (с опасностью ☠ и
слабостями), фракции, места, прочее. У статьи есть выжимка — одна-две фразы
сути; ✨ пишет её сам (одной статье или всем сразу). Рассказчику обычно
уходит только выжимка, а целиком статья — когда существо в сцене или игрок о
нём спросил; на всё — бюджет ~1200 токенов, так кодекс не съедает контекст.
У статьи может быть иллюстрация — арт типичного представителя народа или существа,
вид места: рисует твой Automatic1111, теги составляет модель по статье (их можно
поправить и перерисовать) или загрузи свою картинку. Статья читается как страница
книги: слева арт, справа текст.
У героя и НПС есть «народ»: если он есть в кодексе, рассказчик знает о нём и
о предубеждениях — но только между теми, кто сейчас рядом. По желанию
рассказчик может дописывать кодекс сам (выключено по умолчанию).

**Истории.** Несколько сохранений с изолированным состоянием. Общие для всех —
модель, промт рассказчика, параметры сэмплинга и пул черт.

**Резервные копии.** Раз в сутки при запуске сервер копирует все истории в
`data/backups` (хранятся последние 10); в окне «Истории» → «Резервные копии»
можно сделать копию вручную и восстановить любую историю. Восстановленная
появляется рядом с текущими — ничего не затирается.

**Удобство.** Поиск по всей истории (🔍 или Ctrl+K) с переходом к реплике.
Горячие клавиши: ↑ — править свою последнюю реплику, Alt+R — перегенерировать,
←/→ — листать варианты ответа, Esc — закрыть окно. Набранный ход сохраняется
при обновлении страницы. Пока ждёшь ответа в другой вкладке, у вкладки
появится «✦ Ответ готов» (и, если включить, тихий звонок).

**Классика ролёвки.** Регенерация с откатом состояния, правка любой реплики,
сообщения рассказчику вне истории (OOC), повтор при сбое, «договорить» при
обрыве по лимиту, подсветка речи и действий в тексте.

## Настройки

Модель рассказа и отдельная модель учёта (см. ниже), мир, сценарий, лицо
повествования (третье / «ты» / «вы»), сложность (от мягкой до беспощадной —
конкретные правила, а не настроение), температура и штраф за повтор, глубина
сырой памяти, сжатие, броски, автозапись в лорбук, палитра черт.

### Модели

Рассказу нужна модель с хорошим русским и слабой цензурой, учёту — надёжный
tool calling. Можно ставить разные. Суффикс `:exacto` в слаге направляет на
провайдеров с лучшей точностью вызова инструментов. Reasoning на проходе учёта
выключается принудительно. Переменная окружения `DEBUG=1` печатает причину
завершения каждого ответа — полезно, если ответы обрываются.

### Учётчик на настоящей модели

```bash
npm run eval:sync                                      # модель учёта из настроек игры
npm run eval:sync -- --model deepseek/deepseek-chat    # конкретная модель
npm run eval:sync -- --model a/x,b/y --runs 3          # сравнить модели, по 3 прогона
```

22 типовых хода (получил предмет, вернул долг, ранение, ночь сна, пустой
разговор, безымянный назвал имя, ушёл НПС, истратил стрелу, обещание, встреча,
просроченный срок, ложь, новый персонаж, пустой лист, закреплённое, смерть,
новая цель, покупка, чистое описание, зелье). По каждому проверяется результат:
что учётчик обязан записать и чего делать не должен. Итог — «полнота», «без
лишнего», время и стоимость; подробный отчёт с вызовами — в `data/evals/`.
Ключ берётся из `.env`, партии не трогаются. Сцены лежат в `evals/sync-scenes.js`.

Тесты не ходят в интернет и не трогают твои партии: вместо OpenRouter и
Automatic1111 отвечает подделка, данные пишутся во временную папку. Для
проверки интерфейса один раз поставь Playwright:
`npm i -D playwright && npx playwright install chromium`.

## Безопасность

Ключ OpenRouter живёт только на бэкенде. Не выкладывай сервер в открытый
интернет без аутентификации.

## Факты: закрытие и сроки

- Учётчик видит хронику с номерами (`#3`) и закрывает записи точно: `event {action:"close", id:"#3", outcome}` — исполнено / нарушено / прошло. Перенос — `action:"update"`.
- Тип «Назначено» (plan) — встречи, приёмы, сроки, с полем «Когда» («в полдень», «завтра вечером», «через 2 часа», «18:00»). Срок считается от времени сцены в момент записи; когда часы сцены его проходят, учётчик видит «⚠ СРОК ПРОШЁЛ».
- Факты про будущее («ожидает приём…») показываются учётчику, пока открыты, даже если записаны давно.
- Во вкладке «Факты» можно вручную поставить срок и закрыть запись с исходом.

## Диагностика запросов

Кнопка «🩺 Диагностика» в шапке открывает журнал всех обращений к модели: рассказчик, учётчик (по раундам), продолжение, сжатие истории, теги портрета.

- По каждому запросу: модель и провайдер, время, токены (в том числе на размышления), стоимость, причина окончания, сработавшие откаты (reasoning, tool_choice, мягкий режим).
- Ошибки объясняются по-человечески (ключ, баланс, лимит, модель не найдена, перегрузка, таймаут), сырой текст ошибки виден ниже.
- Предупреждения, даже если запрос прошёл: пустой ответ, обрыв по длине, битые аргументы инструментов, учётчик ответил текстом вместо вызовов.
- Полный запрос (системный промт, сообщения, инструменты) и ответ (текст, вызовы, размышления, сырой JSON) для 20 последних запросов. «Скопировать JSON» — чтобы показать кому-то; «Повторить запрос» — отправить то же самое той же или другой модели, на игру не влияет.
- Красная точка на кнопке — появились новые ошибки, жёлтая — предупреждения.
- Хранится в `data/diag/` (последние 100 записей). Ключ API в журнал не попадает.

## Иллюстрации сцен

Кнопка 🖼 у реплики рассказчика (появляется при наведении) открывает окно иллюстрации.

1. Модель учёта работает раскадровщиком: берёт текст реплики, место, время суток и обстановку **на тот момент** (из снимка хода, а не текущие), приметы тех, кто мог быть в кадре, и выбирает один момент. В кадре — не больше двух персонажей с приметами, толпа — силуэтами.
2. Если у персонажа уже рисовался портрет, его теги берутся дословно — так он похож на свой портрет. Без портрета приметы переводятся из описания.
3. Теги и зерно видны и правятся до генерации. «Нарисовать» — с указанным зерном (пусто — случайное), «Другое зерно» — те же теги заново, «Новый кадр» — попросить модель выбрать другой момент.
4. Картинка встаёт в ленту под текстом, у реплики может быть до 8 картинок (листаются ‹ ›). ✎ открывает кадр с его тегами и зерном, ✕ убирает из ленты. Картинки привязаны к варианту ответа и переживают перелистывание.
5. В настройках («Иллюстрации сцен») — свой стиль, негатив и размер кадра (по умолчанию 1216×832, `rating_safe` и смягчение насилия). Шаги, CFG и сэмплер общие с портретами.

Лица. На широком кадре лицо занимает несколько десятков пикселей, и SDXL рвёт глаза и рот. Поэтому:
- **ADetailer** (расширение A1111: Extensions → Available → adetailer, затем перезапуск webui) находит лица и перерисовывает их в высоком разрешении. Включено по умолчанию, работает и для портретов; «Проверить» в настройках скажет, установлено ли расширение.
- **Hires fix** — второй проход в 1.5× разрешении с denoise 0.4 (только для сцен). Примерно вдвое дольше.
- **Clip skip 2** — Pony обучен на нём, без него качество ниже.
- Раскадровщик держит лица крупными: с персонажами — cowboy shot / upper body / close-up, общий план — только без людей или со спины.

Файлы лежат в `data/scenes/`. Пока идёт генерация, окно можно закрыть и играть дальше — картинка появится сама.

## ✨ Заполнить поле по истории

В карточке НПС (внешность, кто это, характер, статус, что было с героем, чего хочет, изюминка, что скрывает, связи, отношение, настроение, голос) и героя (положение, внешность, описание) рядом с подписью поля есть ✨.

- **Из текста** — модель учёта собирает всё, что история знает о персонаже: реплики, где он упоминается (первые появления и последние, в том числе под прежним описательным именем), последние ходы, предысторию, хронику и остальную карточку — и заполняет поле только тем, что сказано. Если ничего не сказано, так и сообщит.
- **Придумать** — известное плюс правдоподобно придуманное недостающее в духе мира.
- Уже написанное в поле сохраняется и дополняется. Результат подсвечивается и **не сохраняется сам** — поправьте и нажмите «Сохранить»; ↶ возвращает прежний текст.
- У закреплённого поля ✨ нет. Запросы видны в «Диагностике».

## Сжатие истории

Старые сообщения сворачиваются в «Предысторию» пачкой: когда сверх «Сырых ходов в памяти» наберётся ещё половина этого числа (для 20 — при 30 сообщениях срезается до 20). Сжатие идёт **в фоне** после ответа и ход не задерживает; если за это время историю перегенерировали или обрезали, результат отбрасывается и сжатие повторится позже. Запрос идёт без «размышлений» модели. Видно в «Диагностике» как «сжатие истории».

## Несколько героев

Каждый ход помечается героем, за которого он сделан. Когда в истории есть ходы разных героев, рассказчик видит пометки «[Ход за героя …]» и «[Эпизод героя …]» и правило: «ты» — тот, за кого был ход; чужие раны, предметы, знакомства и знания на текущего героя не переносятся. Сжатие истории тоже называет героев по именам. У каждого героя своя сцена: при переключении запоминается, где был прежний, и новому возвращается его место (часы общие). Ходы, сделанные до этой версии, пометок не имеют.

## Инструкция учётчика

По умолчанию — техническая: алгоритм (разбить фрагмент на события → сверить с данными → проверить связки → вывести все вызовы), карта «событие → инструмент», поля НПС, связки последствий (заплатил → деньги + закрыть долг + отношение; ушёл → сцена + статус и т. п.), формат аргументов и запреты. Прежняя включается в настройках («Инструкция учётчика»).

Пустой лист героя: учётчик получает описание героя и правило завести лист (если история уже идёт — по положению на сейчас).

Проверка полноты кодом: после первого раунда код ищет во фрагменте явные признаки (платят/получают, ранение, прошло время, кто-то ушёл, исполнено обязательство из хроники) без соответствующего вызова и только тогда просит модель дописать — в журнале это строка «полнота».
